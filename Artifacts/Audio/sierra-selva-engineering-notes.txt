No se genero ningun RunnerCourse ni contenido de nivel; solo la base de musica/ritmo, per pedido
del usuario ("solo deja ahi lo que astra necesite").

Hits clasificados (ground/air) para usar como base de encounters, mismo formato y mismo proceso
que costa_rhythm.json + ApplyMidiRhythm.cs:
- Artifacts/Audio/sierra_rhythm.json: 174 hits (58 ground, 116 air), regenerado con la duracion
  real corregida.
- Artifacts/Audio/selva_rhythm.json: 260 hits (88 ground, 172 air).
- Estos son intensidad-clasificados, no nota-por-nota literal (los MIDI son transcripciones
  automaticas densas sin separacion limpia de bateria/bajo - mismo caveat que Costa).
- Tools/analyze_costa_midi.py ahora tiene las 3 canciones (costa/sierra/selva) con su duracion
  real; correrlo de nuevo regenera los 3 rhythm.json si hace falta retocar el filtro.

Para armar el RunnerCourse real (Astra):
1. Crear el RunnerCourse.asset (region, speed, duration = duracion real del clip, soundtrack =
   Sierra/SelvaSoundtrack.asset).
2. Disenar platforms/gaps/orbs/jumpPads a mano (o adaptando VerticalPrototype como hizo Costa).
3. Escribir un ApplySierraMidiRhythm.cs / ApplySelvaMidiRhythm.cs (copiar ApplyMidiRhythm.cs,
   cambiar las rutas) para convertir sierra_rhythm.json/selva_rhythm.json en course.encounters,
   una vez que el course ya tenga sus gaps definidos (el script salta encounters que caen dentro
   de un hueco).
4. Marcar notas dudosas y validar de oido antes de dar el ritmo por definitivo - no hecho todavia
   para ninguna de las 3 canciones.
